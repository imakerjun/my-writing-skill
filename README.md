# My Writing Skill

**내 글의 기준을 만들고, AI와 함께 다듬는 스킬.**

**코드로 찾고, LLM과 고치고, 내 미감으로 평가한다.**

초안 한 문단에서 시작합니다. AI가 후보 하나를 제시하면 내가 0·1·2점과 이유를 남깁니다. **그 이유를 다음 글의 지침과 확인 질문으로 옮기고, 다른 문단에서도 통하는지 확인합니다.** 글을 고치면서 내가 어떤 문장을 좋다고 느끼는지도 구체화합니다.

메이커준(임동준)의 우아콘 발표 「AI에게 미감을 가르칠 수 있을까?」에서 소개한 ‘사람냄새 스킬’에서 출발했습니다. 표현 점검과 함께 각자의 목적·말투·판단 이유를 쌓는 흐름으로 확장했습니다.

## 5분 시작

준비물은 **고칠 AI 초안 한 문단**과 **그 글로 전하고 싶은 뜻 한 문장**입니다. 코드 도구를 실행하려면 Python 3.10 이상이 필요합니다. 별도 Python 패키지는 필요 없습니다.

```bash
git clone https://github.com/imakerjun/my-writing-skill.git
cd my-writing-skill
python3 install.py codex
```

새 Codex 대화에서 요청합니다.

```text
$my-writing-skill
이 초안을 고쳐줘. 독자는 [누구]이고, 전하려는 뜻은 [한 문장]이야.
먼저 후보 하나와 수정 이유를 보여줘. 내가 0·1·2점과 이유를 말하면
그 판단을 다음 지침과 eval 질문으로 옮겨줘.
다른 문단에도 적용해서 내 기준이 통하는지 하나씩 확인하자.
```

Claude Code를 사용한다면 `python3 install.py claude`로 설치한 뒤 새 대화에서 `/my-writing-skill`로 요청합니다. 설치기는 선택한 도구의 사용자 스킬 폴더에 이 저장소의 링크만 만듭니다. 같은 이름의 다른 스킬은 덮어쓰지 않습니다. 해제는 `python3 install.py codex --uninstall`입니다.

## 한 문단으로 시작해 내 기준을 쌓기

1. **전할 뜻을 한 문장으로 적습니다.** 누가 읽고 무엇을 이해하거나 해보길 바라는지 적습니다.
2. **AI 후보 하나를 읽습니다.** 코드가 알려준 위치를 참고하되, 뜻과 말투를 살리는 수정을 제안받습니다.
3. **0·1·2점과 근거 구절을 남깁니다.** “좋다”와 함께 무엇이 드러나서 좋은지, 1점이라면 무엇이 빠졌는지 말합니다.
4. **이유를 지침과 질문으로 옮깁니다.** AI의 정리안을 확인한 뒤 내 기준에 남깁니다.
5. **다른 문단에서 다시 확인합니다.** 어긋나면 지침을 고치고, 언제 적용할지도 좁힙니다.

이미 좋아하는 문장이 있다면 [내 글의 기준 템플릿](templates/author-preferences.md)을 `local/author-preferences.md`로 복사해 문장과 이유를 넣어보세요. 없어도 바로 시작할 수 있습니다. 이 파일과 평가는 개인 로컬 자료로 유지합니다. 자신의 글이 아닌 예문이나 AI가 추론한 취향을 내 확정 기준으로 넣지 않습니다.

이 과정은 내가 선택한 이유를 더 명확하게 말해보는 연습입니다. 점수가 올랐다는 이유만으로 미감이나 글쓰기 실력이 향상됐다고 단정하지 않습니다. 모델 가중치를 학습시키는 파인튜닝도 아닙니다.

## 세 단계, 네 역할

| 단계 | 역할 | 실제 도구와 판단 |
|---|---|---|
| 찾기 | 코드 | `scripts/analyze.py`로 문장 길이·문장 앞 연결 표현·반복 위치를 추출 |
| 고치기 | LLM | `SKILL.md`로 문맥을 읽고 적용·보존·보류를 구별 |
| 확인하기 | 독자 관점 | 무슨 뜻으로 읽었는지, 어느 대목에서 다시 읽었는지 질문 |
| 확인하기 | 나의 미감 | 0=이건 아니다 / 1=애매함 / 2=좋다와 근거 구절·이유를 기록 |

평가한 이유 → 스킬 지침·eval 질문 수정 → 다른 문단에서 확인으로 이어갑니다. 스킬을 설치했다고 이 전체 과정이 자동 실행되는 것은 아닙니다. LLM 작업과 저자의 판단을 대화로 연결합니다.

### 숫자는 다시 읽을 곳을 알려줍니다

```bash
python3 scripts/analyze.py eval/cases/03-causality/input.md --output local/before.json
```

문장 수·최대 글자 수·문장 앞 연결 표현 수 등을 JSON으로 얻습니다. 구두점에 의한 문장 분리는 근사입니다. 숫자가 줄었다고 더 좋은 글이라고 판정하지 않습니다.

### 저자의 점수와 이유를 남깁니다

저자가 실제로 점수와 이유를 말한 다음에 기록합니다. 아래는 명령 형식의 예시이며 실제 저자 평가 결과가 아닙니다.

```bash
python3 scripts/record_rating.py local/candidate.md --score 1 \
  --evidence '후보 속 실제 구절' --reason '내가 애매하다고 느낀 이유' \
  --output local/ratings.jsonl
```

저자 대신 점수를 매기지 않습니다. ‘2점에 가까움’과 조건부 평가를 임의로 정수 점수로 바꾸지 않습니다. 점수와 실제 채택 여부도 구분합니다. 자기 기준을 정리할 때는 [미감 기록 틀](templates/judgment-card.md)을 사용할 수 있습니다.

## 좋은 문장은 남겨야 합니다

‘자리’, ‘우리’, ‘그래서’가 있다는 이유만으로 지우지 않습니다. 실제 장소, 화자, 선택의 이유를 드러낸다면 보존합니다. 이미 저자가 고른 문장과 새 AI 제안을 구별하고, 근거가 불분명한 수정은 보류합니다.

공개판의 기본 검토 신호는 [표현 점검표](references/review-signals.md)에 있습니다. 자신의 글에 맞는 보존 기준은 `local/author-preferences.md`처럼 로컬 파일에 작성해 제공하면 됩니다.

## eval에는 고칠 말과 남길 말을 함께 넣습니다

[eval 안내](eval/README.md)의 가상 사례 3개에서 시작할 수 있습니다. 입력 문단만 보고 실제 모델 응답을 받은 뒤 다음처럼 검사합니다.

```bash
python3 scripts/grade.py eval/cases/01-repetition local/eval-run/01.md
python3 -m unittest discover -s tests -v
```

프로그램은 문제 표현·보존 표현·변경 기록을 검사합니다. 문맥과 자연스러움, 저자의 채택은 별도입니다. **프로그램 테스트 PASS는 스킬의 글쓰기 효과를 검증했다는 뜻이 아닙니다.** 2026-10-22에 이전 공개판 v0.1.0으로 세 사례를 실제 실행했고 자동검사 3/3을 통과했습니다. v0.2.0의 개인 기준 축적 흐름을 새로 검증한 결과는 아닙니다. 저자의 미감 점수는 아직 받지 않았습니다. [실행 기록](eval/results/2026-10-22-r62-text-only/manifest.json)과 [상태 파일](eval/status.json)에 모델·입력·출력·검사 범위를 남겼습니다.

## 포함 범위

- 개인 글쓰기 기준을 만들고 퇴고하는 스킬, 코드 신호 추출기, 보존 검사 채점기
- 0·1·2점 기록기와 미감 기록 틀
- 공개용 가상 eval 3개와 프로그램 테스트

미공개 책 원고·저자 평가 로그·합성 인물 데이터·인터뷰 원답은 포함하지 않았습니다. 독자 인터뷰는 선택적으로 따로 진행합니다. 합성 독자를 사용한다면 실제 사람의 반응과 구별해서 기록하세요.

## 기존 사용자와 이름 변경

저장소 이름은 `saramnaemsae-skill`에서 `my-writing-skill`로 바뀌었습니다. 기존 clone에서도 새 원격 주소로 바꾼 뒤 업데이트할 수 있습니다.

```bash
git remote set-url origin https://github.com/imakerjun/my-writing-skill.git
git pull
python3 install.py codex
```

설치기는 이 저장소를 가리키는 예전 `saramnaemsae` 링크만 새 이름으로 옮깁니다. 다른 스킬이나 개인 평가 파일을 덮어쓰지 않습니다. 과거 실행 기록의 이름·버전·해시는 당시 상태로 보존합니다.
