# My Writing Skill

AI가 써준 글을 읽다가 ‘이런 말은 내가 안 쓰는데’ 싶을 때가 있어요. 다시 써달라고 해도 비슷한 문장이 나오고요.

그럴 때 고치고 싶은 문단 하나를 가져와주세요. AI가 고친 글에 **0점, 1점, 2점**을 주고, 왜 그렇게 느꼈는지 이야기해보세요. 그 이유를 다음 글에도 쓸 수 있는 지침으로 남기는 스킬입니다.

우테코 책을 쓰면서 만든 ‘사람냄새’ 스킬에서 시작했어요. 각자 자기 글을 놓고 어떤 표현을 쓰고 싶은지 찾아갈 수 있게 만들었습니다.

## 문단 하나로 시작해보세요

초안 한 문단이면 돼요. 아직 글로 쓰기 어렵다면, 누군가에게 설명하듯 말한 메모를 가져와도 좋습니다. 누구에게 무슨 말을 하고 싶은지부터 같이 이야기해볼 수 있어요.

설치에는 Python 3.10 이상이 필요하고, 따로 설치할 Python 패키지는 없습니다.

```bash
git clone https://github.com/imakerjun/my-writing-skill.git
cd my-writing-skill
python3 install.py codex
```

새 Codex 대화를 열고 이렇게 시작해보세요.

```text
$my-writing-skill
이 문단을 나답게 고쳐보고 싶어.
누구에게 무슨 말을 하고 싶은지 불분명하면 하나씩 물어봐줘.
후보는 하나만 보여줘. 내가 0·1·2점과 이유를 말할게.
괜찮은 기준이 생기면 내 스킬에 남기고, 다른 문단에도 써보자.

[내 초안이나 말로 풀어 쓴 메모]
```

Claude Code에서는 `python3 install.py claude`로 설치한 뒤 `/my-writing-skill`로 시작하세요. 설치기는 이 폴더를 가리키는 링크를 만듭니다. 설치 후에도 저장소 폴더는 그대로 두세요. 같은 이름의 다른 스킬은 덮어쓰지 않고, `python3 install.py codex --uninstall`로 링크를 해제할 수 있어요.

내 글을 넣기 전에 해보고 싶다면 [연습용 문단](examples/first-session.md)을 써보세요.

## ‘좋다’거나 ‘별로다’고 느낀 이유가 필요해요

후보를 읽고 아래처럼 말해주세요.

| 점수 | 지금 내 느낌 | 한 가지 더 알려주세요 |
|---|---|---|
| **0점** | 이건 아니다 | 어느 표현이 걸렸나요? 평소라면 어떻게 말하겠어요? |
| **1점** | 애매하다 | 어디가 달라지면 쓰고 싶을까요? |
| **2점** | 좋다 | 어떤 구절이 마음에 들었나요? 왜 좋았나요? |

말을 잘 정리해서 답할 필요는 없어요. ‘뜻은 맞는데 제가 동료한테 이렇게 말하진 않을 것 같아요’ 정도로 시작해도 됩니다. AI가 이유를 듣고 다음에 쓸 지침을 제안하면, 내 뜻과 맞는지 보고 반영해주세요.

그다음에는 다른 문단에 써봅니다. 앞에서는 좋았던 지침이 이번에는 어색할 수도 있어요. 그때는 어느 글에 쓸 기준인지 범위를 좁히면 됩니다. 내가 어떤 글을 좋아하는지 더 구체적으로 말해보는 연습이기도 하고요.

## 코드, LLM, 사람이 나눠서 해요

| 맡길 일 | 이렇게 해봐요 |
|---|---|
| **코드와 LLM으로 표현 점검하기** | 코드는 자꾸 고치는 표현과 반복을 찾고, LLM은 앞뒤 문장을 읽으며 고칠지 살릴지 살펴봅니다. |
| **나와 LLM이 전할 말 찾기** | 이번 글에서 꼭 전할 말을 정하고, 핵심 문단 하나를 놓고 점수와 이유를 주고받아요. |
| **독자에게 다시 읽혀보기** | 어떤 뜻으로 읽었는지, 어디서 막혔는지 물어봅니다. 중요한 리뷰부터 반영하고 다시 보여주세요. |

이번 글의 독자와 전할 말은 [짧은 메모](templates/brief.md)로 남겨두세요. 글이나 장이 달라지면 이 메모도 바꿉니다.

### 자꾸 고치는 표현은 코드가 찾게 하세요

[개인 작업 폴더](references/feedback-loop.md)를 만들었다면 `checks.json`에 점검할 말을 적어보세요. 검사할 문단은 그 폴더의 `draft.md`에 저장합니다.

```json
{
  "watch": ["결국", "매우"],
  "preserve": ["우리 팀", "그래서"]
}
```

```bash
python3 scripts/analyze.py local/my-voice/draft.md \
  --config local/my-voice/checks.json --output local/my-voice/before.json
```

`watch`는 다시 읽어볼 말, `preserve`는 유지할지 살펴볼 말이에요. 찾았다고 무조건 지우거나 남기지는 않습니다. 고친 뒤에는 같은 설정으로 다시 검사해보세요. 숫자가 줄었더라도 내 뜻이 잘 전달되는지는 읽어봐야 해요.

[어떤 표현부터 살펴볼까요?](references/review-signals.md) · [코드가 세는 범위](references/signals.md)

### 독자 리뷰는 중요한 것부터 반영해보세요

이번 글을 읽을 사람은 무엇을 알고 있고, 왜 이 글을 읽을까요? 그 사람에게 어떤 뜻으로 읽었는지 물어보세요. 여러 리뷰가 오면 내 의도에 맞는 것 하나부터 고쳐보면 됩니다.

실제 독자에게 부탁해도 좋고, LLM에 독자 역할을 맡겨 미리 살펴볼 수도 있어요. LLM의 반응은 실제 독자의 응답과 구분해 남깁니다. Nemotron Personas Korea를 쓰려면 실제 데이터 행과 출처가 별도로 필요해요. [독자 리뷰 안내](references/reader-review.md)에 진행 방법을 적어두었습니다.

## 내 이름으로 설치해서 쓰고 싶다면

기록을 모을 개인 폴더부터 만들어주세요. 명령은 이 저장소 폴더에서 실행합니다.

```bash
python3 scripts/workspace.py init local/my-voice --name my-voice
```

AI에게 이 폴더를 알려주고, 초안과 내가 준 점수·이유를 남겨달라고 하세요. 제안받은 지침 중 쓰기로 한 것만 확인해두면 내 스킬로 만들 수 있습니다.

```bash
python3 scripts/workspace.py build local/my-voice
python3 local/my-voice/skill/my-voice/install.py codex
```

새 대화에서 `$my-voice`로 불러보세요. 내가 확인한 지침과 이유, 이번 글의 메모, 코드 점검 설정과 평가 질문이 들어 있습니다. 만든 스킬은 원래 저장소 없이도 설치해서 쓸 수 있어요.

기록하고 지침을 확인하는 명령은 [내 스킬로 남기는 방법](references/feedback-loop.md)을 따라 해보세요. 확인하지 않은 지침은 내보내지 않고, 기존 출력 폴더도 덮어쓰지 않습니다. 개인 파일을 두는 `local/`은 Git에서 제외돼 공개 저장소에 자동으로 올라가지 않아요. 생성한 스킬에도 내 글과 평가가 들어갈 수 있으니, 공유하기 전에는 내용을 살펴봐주세요.

## 다음 글에서도 잘되는지 확인하려면

고치기로 한 표현과 유지할 표현을 테스트에 적어둘 수 있어요. 실제 모델이 고친 글을 받은 뒤, 기대한 대로 바뀌었는지 코드로 검사합니다. 뜻이나 말투가 괜찮은지는 따로 읽고 판단하고요.

[eval 안내](eval/README.md)에 `expected.json`을 만드는 방법과 공개 예문 세 개, 실제 실행 기록을 모아두었습니다. `planted`, `traps` 같은 파일 속 이름도 거기서 설명해요. 이 이름들은 이 저장소의 형식입니다.

현재 버전의 검사 상태는 [eval/status.json](eval/status.json)에서 볼 수 있어요. 예전 버전의 모델 실행 결과와 지금 버전의 프로그램 테스트 결과를 나눠 기록했습니다. 내 스킬을 만드는 과정은 지침과 참고할 내용을 바꾸는 방식이며, 모델을 파인튜닝하는 것은 아닙니다.
