# 독자와 원고를 같이 읽어보기

누가 읽을 글인지부터 정해보세요. 같은 글이라도 처음 배우는 사람과 실무에서 쓰려는 사람은 다른 곳에서 막힐 수 있어요. 읽는 목적과 이미 아는 것을 짧게 적고, 그에 맞는 독자를 고릅니다.

## 실제 행에서 독자를 고릅니다

`scripts/personas.py status`는 다운로드하지 않고 `HF_HOME`의 캐시를 확인합니다. 없다면 저장 위치와 용량부터 확인해주세요. `prepare --download`는 사용자에게 다운로드 확인을 받은 뒤 실행합니다. 압축 데이터는 약 1.85GB이며, 다른 도구가 변환 캐시까지 만들면 약 5.76GB가 필요할 수 있어요. 이 도구는 캐시의 parquet를 직접 읽습니다.

필요한 라이브러리가 없다면 `uv run --with datasets --with pandas python scripts/personas.py ...`로 실행할 수 있어요. `HF_HOME`은 기존 캐시 경로를 유지합니다. 조건에 맞는 후보를 만든 뒤 uuid로 독자를 선택하세요. 검색 결과는 전체 한국인을 대표하는 표본이 아닙니다.

`profile` 원문은 바꾸지 않고, `reading_purpose`와 `already_knows`에 이번 글을 읽는 목적을 별도로 적습니다. 원본 필드의 해시와 uuid·revision·출처를 함께 남깁니다. 임의로 만든 인물을 실제 데이터 행이라고 하지 않습니다.

## 워크숍은 이렇게 진행해보세요

[저자 워크숍 소개 글](https://mproject2017.tistory.com/entry/자소서-리뷰-워크숍-퓰리처상에-빛나는-저자워크숍-상세소개)의 진행 순서에서 요약·긍정적 피드백·개선 제안·저자의 질문을 가져와 합성 독자 대화에 맞췄습니다. 원문의 역사 설명이나 효과 주장을 이 도구의 검증 근거로 쓰지는 않습니다.

1. 저자가 읽힐 문단을 고릅니다. 원하면 소리 내어 읽거나 이번에 궁금한 점을 짧게 말합니다.
2. 독자는 먼저 어떤 뜻으로 읽었는지 요약합니다. 첫 반응을 볼 때는 기대하는 정답을 미리 알려주지 않습니다.
3. 좋았던 구절과 이유, 고치면 좋을 구절과 제안을 받습니다. 여러 독자라면 서로의 답을 보기 전에 첫 반응을 따로 받습니다.
4. 저자는 우선 듣고 메모합니다. 이후 궁금했던 점을 질문합니다. 반박부터 하기보다 어떤 구절 때문에 그렇게 읽었는지 물어보세요.
5. 반영할 리뷰를 고릅니다. 0점은 반영하지 않음, 1점은 보류, 2점은 반영할 만함이에요. 원고에 준 점수와 구분해 이유 한 줄을 남깁니다.
6. 중요한 리뷰 하나부터 고치고 같은 독자에게 다시 보여줍니다. 이해한 뜻과 걸린 구절이 어떻게 달라졌는지 확인합니다. 필요한 만큼만 반복합니다.

이 점수는 저자가 직접 줍니다. AI가 대신 승인하거나, 사용자의 응답 없이 다음 평가까지 진행하지 않습니다. 실제 연락·인터뷰 발송은 별도 허락이 필요합니다.
