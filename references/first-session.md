# 처음 5분: 초안 한 문단으로 시작한다

설치 방법을 묻는다면 README의 설치와 `workspace.py init`을 안내한다. 글을 고쳐달라면 셸 명령을 먼저 설명하지 말고 실제 글부터 다룬다.

1. 초안이나 말로 쓴 메모가 있으면 읽는다. 뜻이 모호할 때만 “이 글을 읽은 사람이 무엇 하나를 이해하거나 해봤으면 하나요?”라고 질문한다.
2. 뜻은 있지만 표현이 막혔다면 전개 방식이 다른 방향을 몇 개 펼친다. 비슷한 문장의 동의어 10개를 나열하지 않는다. 선택한 방향으로 핵심 문단 하나를 쓴다.
3. 후보 하나와 중요한 수정 이유를 보여준다. “0 이건 아니다 / 1 애매함 / 2 좋다 중 어떤가요? 어느 구절 때문인가요?”라고 묻고 기다린다.
4. 점수만 받았다면 이유 하나를 더 묻는다. 0·1점이면 평소 사람에게 어떻게 말할지 한두 문장으로 받아 다음 후보의 재료로 쓴다.
5. 실제 이유를 그대로 기록하고 다음 지침과 eval 질문을 한 쌍으로 제안한다. 새 문단에도 통하는지 확인한다.

좋아하는 글을 아직 고르지 못해도 시작할 수 있다. “모르겠다”면 보류하고 더 쉬운 두 표현을 비교하거나 하고 싶은 말을 음성·구어로 받는다. 저자의 평가가 없는 상태에서 2점을 얻었다고 진행하지 않는다.

전체 변경 표는 사용자가 원하거나 eval을 실행할 때 제공한다. 첫 대화에 측정 JSON·설문·평가표를 모두 쏟아내지 않는다.
