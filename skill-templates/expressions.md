# AI 냄새 표현 점검

이 스킬은 글에서 다시 읽을 표현을 찾는다. AI가 쓴 글인지 판별하지 않는다. [기본 목록과 사용자 판단](checks.json)을 사용하되, 기본 목록을 저자가 평가한 결과로 소개하지 않는다.

## 처음 시작하기

[대화 말투](references/first-session.md)를 읽고 편한 존댓말로 말한다. 원고를 받았다면 그 원고부터 본다. 점검어를 정하려는 요청이라면 [예문](templates/expression-examples.json) 하나를 보여주고 “이 표현은 어떻게 들리세요? 0점은 어색해요, 1점은 애매해요, 2점은 괜찮아요예요. 어느 말 때문인지도 알려주세요”처럼 묻는다. 한 번에 모든 단어를 평가하게 하지 않는다.

실제로 받은 점수와 이유만 `scripts/expression_preferences.py rate 작업폴더 --candidate 예문.md --term 표현 --score 점수 --reason 이유 --evidence 실제구절 --scope 어떤글`로 기록한다. 작업 폴더가 없다면 `init 작업폴더 --base-config 이스킬/checks.json`으로 먼저 만든다. 같은 단어라도 문맥에 따라 0점과 2점이 함께 있을 수 있다. 1점은 보류하고 AI가 대신 결론 내리지 않는다. 사용자가 등록해달라고 했다면 같은 확인을 반복하지 않는다.

## 코드로 찾고 문맥으로 고치기

1. 개인 작업 폴더의 `checks.json`이 있으면 우선하고, 없으면 이 스킬의 `checks.json`으로 `python3 scripts/analyze.py 원문.md --config 설정.json --output 검사.json`을 실행한다. 스크립트 경로는 이 스킬 폴더 기준이다.
2. 일치한 구절의 앞뒤와 점수를 준 예문·범위를 읽고 수정·유지·보류를 정한다. `watch`는 삭제 명령이 아니며 `preserve`도 모든 문맥의 보존 명령이 아니다. [표현 예시](references/review-signals.md)와 [측정 범위](references/signals.md)는 필요할 때 읽는다.
3. 사실·화자·인용·이름을 보존해 문단 하나를 고친다. 없는 경험과 감정을 보태지 않는다. 같은 설정으로 다시 검사한다. 횟수 감소를 글의 품질 향상으로 말하지 않는다.
4. 보통은 고친 문단과 중요한 이유 하나만 보여주고 저자의 답을 기다린다. 원고를 직접 수정해달라는 요청이 없으면 후보로 보여준다. eval 요청에는 `## 수정본`, `## 변경 기록` 형식을 지킨다.
