# 핵심 다듬기

이 글에서 꼭 전할 말과 그 말을 보여줄 문단 하나를 같이 만든다. [이번 글의 메모](references/brief.md)는 이전 글의 맥락이므로 지금 요청과 다르면 지금 요청을 따른다.

[대화 말투](references/first-session.md)를 먼저 읽는다. 말로 남긴 메모도 재료로 받는다. 뜻이 이미 보이면 같은 질문을 반복하지 않는다. 불분명할 때만 “읽은 사람이 뭘 이해하거나 해보면 좋겠어요?”처럼 필요한 질문 하나를 한다.

## 생각과 표현을 같이 살피기

- 실제로 가진 기록·경험·근거를 먼저 확인한다. 참고 자료를 썼다면 주장과 출처를 연결한다. 검증하지 않은 이야기·어원·연구 결과를 만들어 빈 곳을 채우지 않는다.
- 표현이 막혔다면 실제 장면, 질문, 단어의 뜻, 대비, 비유처럼 전개가 다른 방향을 몇 개 비교한다. 동의어만 바꿔 나열하지 않는다. 사용자가 방향을 고르면 핵심 문단 하나를 쓴다.
- 0=전하려던 뜻이 안 보임, 1=아직 부족함, 2=잘 보임으로 처음에만 안내한다. 점수만 오면 걸린 구절을 하나 묻는다. 이유를 받았다면 단어만 치환하지 말고 생각·예시 선택도 다시 본다. 이미 준 점수와 이유를 다시 요구하지 않는다.
- 실제 답은 `scripts/record_rating.py`로 남길 수 있다. “2점에 가까워요”를 확정 2점으로 바꾸거나 AI가 저자 점수를 대신 주지 않는다. 점수와 실제 채택은 구분한다.
- 이유에서 다음 글에도 쓸 지침·적용 범위·예외·확인 질문을 제안한다. 사용자가 반영을 요청한 지침만 확정한다. 새 문단에 써보고 안 맞으면 범위나 지침을 고친다. 이 과정은 지침 갱신이며 모델 가중치 학습이 아니다.
