# 사람냄새 스킬

**코드로 찾고, LLM과 고치고, 내 미감으로 평가한다.**

우테코 책 집필용 사람냄새 v2.3의 판단·보존 원칙을 공개용으로 옮겼다. 저자가 고른 표현을 모두에게 적용할 문체 규칙으로 만들지 않는다.

## 1. 먼저 전할 뜻을 확인한다

지정한 초안, 독자, 전할 생각 한 문장, 읽은 뒤 기대하는 변화를 확인한다. 이미 대화에 있으면 다시 묻지 않는다. 뜻이 불명확해 문장 선택이 달라질 때만 짧게 묻는다. 저자 원문·명시적 채택·미채택 AI 초안을 구별한다.

원문을 보존하고 퇴고 후보를 별도 파일이나 대화에 제시한다. 사용자가 현행 파일 수정을 요청했으면 그 범위에서 수정한다. 다른 원고·보관 자료를 함께 고치지 않는다. 기존 문체와 화자를 유지한다.

## 2. 코드는 다시 읽을 위치를 찾는다

필요할 때 이 스킬 폴더 기준으로 실행한다.

```bash
python3 scripts/analyze.py 원문.txt --output local/run-01/before.json
```

문장 수·최대 길이·문장 앞 연결 표현·표면형 반복을 확인한다. 구두점 기준 문장 분리는 근사다. 숫자 감소를 퇴고 목표나 품질 점수로 쓰지 않는다. 한국어의 보편적인 글자 수·접속사 개수 상한을 만들지 않는다. 자세한 측정 범위는 [references/signals.md](references/signals.md)를 읽는다.

## 3. LLM은 문맥을 보고 적용·보존·보류를 정한다

[references/review-signals.md](references/review-signals.md)의 표현은 점검 후보다. 같은 단어가 보여도 다음을 먼저 확인한다.

- **적용:** 뜻과 사실을 유지하면서 고칠 이유가 분명한 AI 초안의 표현.
- **보존:** 구체적인 행동·장소·인과·화자·인용·핵심 개념 또는 저자가 명시적으로 남긴 말.
- **보류:** 의도 가능성이 있거나 근거·작성 주체가 불명확한 표현. 바꾸지 않고 제안과 질문만 남긴다.

`local/author-preferences.md` 같은 저자 기준이 제공되면 먼저 읽는다. 없으면 보존 목록이 있는 척하지 않는다. 소리 내 말할 때 자연스러운지 보되, 모든 글을 존댓말·단문·질문형으로 통일하지 않는다.

단어만 동의어로 바꾸고 비슷한 설명을 반복하지 않는다. 문장을 줄이며 여건·고민·선택 이유와 화자를 지우지 않는다. ‘우리’, ‘그래서’가 인과와 주체를 드러내면 남긴다. 확인되지 않은 장면·발언·동기·성과를 만들지 않는다. 원래 비유가 성립하지 않으면 목적을 계속 덧붙이기보다 예시 선택을 다시 살핀다.

후보는 한 번에 하나만 제시하고 다음 표를 남긴다. 실제 변경이 없으면 빈 표와 `적용 0건, 보류 0건`을 명시한다.

| 유형 | before | after | 이유 | 상태 |
|---|---|---|---|---|

수정 후 다시 읽어 새 생성투·뜻의 변화·불필요한 해설이 들어왔는지 확인한다. 원문과 후보에 같은 코드를 실행해 수치 차이를 관찰값으로만 제시한다.

## 4. 저자가 점수와 이유를 남긴다

0=이건 아니다 / 1=애매함 / 2=좋다. 저자에게 근거 구절과 이유를 묻고 답을 기다린다. 대신 점수를 주지 않는다. ‘2점에 가까움’이나 조건부 평가는 임의로 2점으로 바꾸지 않는다.

정수 점수를 실제로 받았을 때만 [scripts/record_rating.py](scripts/record_rating.py)로 후보·점수·원래 이유를 로컬에 남긴다. 이유가 없으면 추측해 채우지 않는다. 조건부·정수 외 평가는 대화 원문으로 별도 보존한다. [templates/judgment-card.md](templates/judgment-card.md)를 기록 틀로 쓸 수 있다.

이유에서 다음 지침과 확인 질문을 **제안**한다. 저자의 선택을 확인하기 전 AI 제안을 채택된 문체 정답으로 넣지 않는다. 새 지침으로 다른 문단을 고쳐 다시 평가한다. 이것은 프롬프트·평가기준의 수정이며 모델 가중치 학습이 아니다.

## 5. eval은 고칠 말과 남길 말을 함께 확인한다

[evaluation 안내](eval/README.md)에 따라 입력·저자 맥락만 보고 실행하고 `expected.json`은 실행 모델에게 숨긴다. 응답 생성과 프로그램 채점을 구별한다. 개발에 쓴 예시와 새 문단 검증도 구분한다.

`scripts/grade.py`는 문자열·보존·기록 형식의 검사다. 코드 PASS만으로 뜻 보존·자연스러움·저자 채택까지 통과했다고 하지 않는다. 원문 문체가 존댓말이면 임의로 `~한다` 기준을 적용하지 않는다.

독자 관점이 필요하면 실제 독자에게 무슨 뜻으로 읽혔는지·다시 읽은 대목을 묻는다. 사용자가 합성 인터뷰를 요청하고 관련 데이터와 도구가 있을 때만 별도로 실행한다. 합성 응답은 예상 질문을 찾는 자료이며 실제 사람의 반응이나 저자 평가를 대신하지 않는다. 이 저장소는 페르소나 데이터나 인터뷰 응답을 포함하지 않는다.

# 다시 읽을 표현의 신호

원본 사람냄새 v2.3 체크리스트를 공개용으로 정리했다. 단어 금지 사전이나 모든 독자에게 적용되는 좋은 글의 정의가 아니다.

| 점검 후보 | 문맥에서 볼 것 |
|---|---|
| 리듬·매듭·여정·켜켜이·~하는 자리·~하는 순간 | 추상적인 해설인지, 실제 장소·시간·과업을 가리키는지 |
| 빈 곳을 채운다·무게중심을 둔다·한 겹 더 | 누가 어떤 행동을 했는지 흐려졌는지 |
| 의미·가치·깊이를 만든다 | 무엇이 어떻게 달라지는지 원자료에서 확인할 수 있는지 |
| A도 B도 C도·같은 대구 반복 | 서로 다른 실제 사례인지, 같은 설명만 반복하는지 |
| 오롯이·고스란히·촘촘히·단단히 | 이 말이 의미를 더하는지 |
| 대시·가운뎃점 | 부연 때문에 읽기가 끊기는지, 단순한 명사 나열·인용인지 |
| ~인 셈이다·~기 마련이다 | 같은 대목에서 상투 마무리가 반복되는지. 단독 사용을 자동 삭제하지 않는다 |
| 겹말·이중 관형절·명사와 동사의 어긋난 짝 | 의미를 잃지 않고 구체적으로 풀 수 있는지 |

인용문·명명된 개념·저자 확정 표현·필요한 인과와 화자를 우선 보존한다. 저자에게 없던 감정이나 경험을 보태는 일을 ‘사람냄새’로 해석하지 않는다.

# 코드가 세는 것

- 글자 수: Python 문자열의 Unicode 코드 포인트 수. 공백 포함/제외를 구분한다.
- 어절 수: 공백으로 나눈 단위. 형태소나 영어 단어 수가 아니다.
- 문장: 문단과 구두점을 기준으로 나눈 근사치. 인용·약어를 직접 확인한다.
- 연결 표현: 미리 나열한 표현이 문장 앞에 나온 경우만 센다. 한국어의 모든 접속 표현·연결 어미 수가 아니다.
- 반복: 같은 표면형의 반복. 형태소를 정규화하지 않는다.

긴 문장·접속 표현은 다시 읽을 위치를 찾는 데 쓴다. 횟수를 줄였다고 좋은 글이 됐다고 판정하지 않는다. 문장 분리나 인과·화자의 보존 여부는 LLM과 사람이 문맥에서 확인한다.
