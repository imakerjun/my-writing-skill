# 사람냄새 eval

고칠 표현을 찾는지와 남겨야 할 말을 지키는지를 함께 검사한다. 이 폴더의 세 사례는 **공개용으로 새로 구성한 가상 예문**이다. 미공개 책 원고나 저자·독자의 실제 반응을 포함하지 않는다.

## 모델 실행과 채점을 나눈다

1. 에이전트에 `SKILL.md`, 필요한 참고 문서, 해당 사례의 `input.md`를 준다. `expected.json`과 `program-fixtures/`는 보여주지 않는다.
2. `## 수정본`, `## 변경 기록` 형식으로 실제 응답을 받아 `local/eval-run/`에 저장한다.
3. 저장한 응답에 프로그램 채점기를 실행한다.

```bash
python3 scripts/grade.py eval/cases/01-repetition local/eval-run/01.md
```

4. 프로그램 결과와 별도로 뜻 보존·연결·자연스러움·저자 채택을 확인한다. 필요하면 같은 조건을 여러 번 실행해 결과가 달라지는지도 기록한다.
5. 기준을 고칠 때 쓴 개발 사례와 새로운 문단을 구별한다. 새 문단을 본 뒤 지침을 고쳤다면 다음 검사에는 또 다른 문단을 쓴다.

## 채점기가 확인하는 범위

- 문제 표현(planted)을 수정하거나 기록표에서 보류했는지.
- 보존 표현(trap)이 **수정본 본문**에 남았는지. 변경 기록에만 있으면 보존으로 인정하지 않는다.
- 변경 기록이 있는지. 수정하지 않았다면 입력과 본문이 동일하고 0건을 명시했는지.
- 원문이 `~한다`인 사례에서 존댓말 전환 신호가 있는지. 의심 신호는 직접 읽어 확인한다.

문자열이 사라졌다는 사실은 의미를 잘 고쳤다는 증거가 아니다. `PASS`는 프로그램 검사 범위에서만 통과했다는 뜻이다.

## 채점기 자체 점검

```bash
python3 -m unittest discover -s tests -v
```

`program-fixtures/`는 위 테스트를 위한 **고정 형식 예시**다. 모델이 스킬을 실행해 생성한 응답이 아니므로, 이를 채점한 PASS를 스킬 효과나 저자 만족도로 소개하지 않는다. 현재 공개 패키지의 모델 평가 상태는 [status.json](status.json)에 있다.

## 실제 실행 기록 · 2026-10-22

공개 스킬 v0.1.0과 위 가상 예문 세 개를 Claude Code CLI에 제공했다. 실행 JSON의 `modelUsage`에 기록된 모델은 `claude-fable-5-1`이다. 세 사례 모두 실제 수정본과 변경 기록이 생성됐고 프로그램 자동검사 3/3을 통과했다. 저자 미감 점수·실제 채택 여부는 아직 평가하지 않았다.

- [실행 조건·해시·시각·모델·검사 결과](results/2026-10-22-r62-text-only/manifest.json)
- [겹말 수정 결과](results/2026-10-22-r62-text-only/01-repetition.md)
- [구체적인 장소 표현 보존 결과](results/2026-10-22-r62-text-only/02-preserve.md)
- [인과를 잇는 ‘그래서’ 보존 결과](results/2026-10-22-r62-text-only/03-causality.md)

이 실행에서는 도구를 비활성화하고 스킬의 선택사항인 코드 분석을 생략했다. 모델에는 스킬·참고 문서·입력만 제공했고, 격리한 빈 작업 폴더에서 실행해 `expected.json`·채점기·고정 테스트 답안을 읽지 못하게 했다. 파일 탐색을 시도하다 끝난 [선행 실행](results/2026-10-22-r62/manifest.json)과 인증 오류는 결과를 별도 보존하고 성공 수에서 제외했다. 텍스트만으로 작업을 끝내도록 실행 지시를 명확히 한 뒤 다시 실행했다. 스킬 본문을 수정해 성능이 좋아졌다는 비교 실험은 아니다.

재현하려면 로그인된 Claude Code CLI가 필요하다. 다음 명령은 실제 모델을 호출하며 사용량이 발생한다. 결과는 기본적으로 git에서 제외되는 `local/eval-run/<실행시각>/`에 저장한다.

```bash
python3 eval/run_text_eval.py
# 한 사례만 실행
python3 eval/run_text_eval.py --case 03-causality
```

실행기는 모델 프로세스 오류·오류 JSON·빈 응답이면 채점을 건너뛰고 실패로 기록한다. 채점기는 수정본이나 변경 기록 없이 도구 호출문만 나온 응답을 형식 실패로 처리한다. 이 형식 검사는 채점기 자체의 회귀 테스트로도 확인한다.
